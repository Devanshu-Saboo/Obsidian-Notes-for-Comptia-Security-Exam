### Restarts
After implementing a patch, it is common to restart the system to fully implement the patch. This could include things like the Operating System, Particular Services or even just signing out every user out of the application and restarting it.

### Legacy Applications
There may be some applications that are running since a long time ago which may no longer receive security patches from its developers making it very risky to still continue running on the system as any attacker can gain access to the internal network using the legacy systems. It is always advisable to replace such software as soon as possible and find proper workarounds for each of these software. 

### Dependencies
If an application A cannot execute itself without application B first being installed, we call this as a dependency and in IT we need to very careful about such software as whilst making changes to software B we must also ensure to not break software A from running properly. An example of this may be a firewall and a switch which operate on different devices but you would still need to ensure any new firewall rules do not break any current switches routing packets through the network.

### Documentation
Required with each new update made to the system to transfer accurate knowledge ahead. This may also require updating diagrams mentioned in the documentation, policies, procedures, versions etc.

### Version Control
Simply track the versions of the software in which business can proceed as intended. This not includes software but also Operating system versions, Router or switch configurations, Firewall rules etc. 

It is also a good idea to take a snapshot of the system in its optimal working state to ensure that if anything breaks, it is easy to revert back to an old system when it was still in full capacity.
